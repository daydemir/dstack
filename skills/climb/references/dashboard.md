# Climb dashboard guidance

Use two views: a lab notebook during the search and a peak report when it stops.
Prefer the project's existing reporting surface or a lightweight local report.
A shared climb list is optional when several climbs need attention. The
presentation reads the experiment record; it does not become a second source of
truth or a prerequisite for running the climb.

## Lab notebook

Make the objective, metric direction and units, baseline, best result, current
state, and stopping rule easy to find. Plot attempts or elapsed time against
score, showing individual outcomes and best-so-far. Distinguish retained,
rejected, failed, and still-maturing experiments using labels or shapes as well
as color. A failed evaluation is not a measured zero.

Selecting an attempt should reveal its hypothesis, change or commit, evaluation
output, and decision. Show uncertainty or repeated-run variation where it
matters. For a council, expose the individual judges, pinned rubric, and
agreement rather than hiding them behind one average. For live outcomes, show
cohort dates, observation window, coverage, and pending measurements.

Keep the editable surface and regression constraints accessible. Scores from
different metrics, evaluators, or observation windows are not directly
comparable. Label illustrative data explicitly. Use readable labels, responsive
charts, and keyboard-accessible controls if the report is interactive.

## Peak report

Lead with the baseline and best independently validated outcome, including units
and uncertainty. State whether the climb reached its target, plateaued, used its
budget, or stopped on a blocker. Preserve an inconclusive result as inconclusive.

Link the retained artifact and supporting evidence. Summarize retained changes,
failed approaches, constraint checks, and remaining limitations. Attribute gains
to individual changes only when experiments establish that attribution.

Offer a starting point for the next climb: lessons, hypotheses, and any proposed
scope or metric changes. Preparing that starting point does not itself launch a
new run or expand its authority.
